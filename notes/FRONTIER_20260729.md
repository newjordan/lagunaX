## What their two rungs mean *here*

### 1) Inverse-permutation scatter

**Their problem:** second full `argSort` of **4096** route indices per sparse prefill layer.

**Ours:** router uses `ggml_argsort_top_k(probs, 8)` which is implemented as **full DESC argsort of 256** then a VIEW of top-8 — not a 4096-token switch packing inverse.

| Item | Status |
|------|--------|
| Exact inverse-scatter of token-route order | **Low relevance** for serial decode N=1; prefill may pack differently |
| Full sort of 256 when only top-8 needed | **Medium** — waste per MoE layer × ~39 sparse layers |
| `GGML_OP_TOP_K` kernel exists on SYCL | **Unused** by graph (`argsort_top_k` path) |

**Better B70 analogue:** teach graph (or fuse) to use true top-k / fused router so we never fully sort 256 floats when k=8.

### 2) lm_head candidate-mask inlining

**Their problem:** vocab=**100352**, coarse+delta prune with standalone mask launch (~100 KB mask + ~588 KiB BF16 coarse / token).

**Ours:** `laguna.cpp` does full  
`build_lora_mm(model.output, cur)` → dense **vocab × embd** GEMV every decode step.  
**No prune / mask path in llama.cpp for Laguna.**

Rough traffic (Q4_K):

| Op | ~weight bytes / decode step |
|----|----------------------------:|
| **lm_head full** | **~116 MB** |
| MoE gate+up (8× dual) | ~9 MB |
| MoE down (8) | ~5 MB |

So **lm_head is the largest single weight stream per token** if the GEMV is memory-bound. Their mask inline is a *refinement of an existing prune*; we still need a **prune design** that stays golden-bitexact (or accept a separate non-golden speed track — we should not for scored claims).

**Transfer lesson (adopt):** kill-switches + same-binary tip oracle before any float-surface kernel.

### Critical finding: router fuse is off

```cpp
// topk-moe.cpp
if (args.prob_bias) {
    return 0;  // Laguna has ffn_exp_probs_b → always true
}
```

So every MoE layer pays **unfused** sigmoid → add(bias) → **full argsort(256)** → view → get_rows → sum-norm → scale as separate graph nodes. Integer/exact-friendly fuse with bias support is a **high-transfer** candidate (matches their “integer / textual copy transfers” doctrine).

### Critical finding: prefill `mul_mat_id` falls off the fast path

```cpp
if (ne12 == 1) {
    if (ggml_sycl_mul_mat_id_mmvq_fused(...)) return;
}
// else: D2H ids, stream->wait(), host counting sort, H2D mapping, ...
```

Serial decode is fine. **pp512** pays host sync + scatter-gather setup every MoE matmul when tokens>1. Package multi-token path is richer but whole package tree still loses ~28% solo pp for other reasons — do **not** wholesale-port.

1. **Tip oracle from the same binary** with all kill-switches forced off-package.
